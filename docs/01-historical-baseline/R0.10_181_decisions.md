# CommerceCore — R0.1–R0.10 Historical Decision Register

> English rendering of the original 181 selections; this translation does **not** newly ratify any choice. The master source is preserved separately, and later policies D-01–D-07 must be read alongside it.

**Original decision statuses:** 26 `ACCEPTED` (R0.1/R0.2) and 155 `PROPOSED — SELECTED` (R0.3–R0.10). **Evidence:** `NOT_EVALUATED` unless individually evidenced elsewhere.

## R0.1 — ACCEPTED

### R0.1-01 — Product identity

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Reusable headless commerce framework and SaaS offering; separate the commercial engine from the Control Plane; independent installation is a progressive goal.

### R0.1-02 — Initial operating model

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Start on shared multi-tenant infrastructure, with dedicated deployments as a future possibility.

### R0.1-03 — Company and brand

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

A company may operate multiple stores with separate or shared catalogs.

### R0.1-04 — Frontend independence

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Expose backend functionality through frontend-agnostic APIs and SDKs; Angular is the reference frontend.

### R0.1-05 — Customization

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Use validated configuration and interface-based adapters; prohibit arbitrary tenant-supplied executable code.

### R0.1-06 — Product scope

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Support both digital and physical goods in the product vision; the initial vertical is digital.

### R0.1-07 — Buyer model

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Keep commercial buyer profiles isolated per company, potentially linked to a common technical identity.

### R0.1-08 — Source availability

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Use a public open-source repository; the precise license is still only a proposal, with Apache-2.0 a candidate.

### R0.1-09 — First delivery

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Deliver an evolvable deployable MVP; do not equate a demo with certified production or real-sales readiness.

### R0.1-10 — Developer environment

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Prefer WSL2/Linux and VS Code.

### R0.1-11 — Repository organization

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Use a coordinated monorepo with Nx and pnpm.

### R0.1-12 — Primary objective

**Decision status:** `ACCEPTED` · **Evidence:** `NOT_EVALUATED`

Favor deep architectural learning and verifiable production-oriented evidence over development speed.
